# Как адаптировать шаблон под клинику

Проект состоит из трёх независимых страниц React. Vite собирает главную, «Услуги» и «О клинике» в отдельные HTML-файлы. JSX определяет разметку, компоненты и анимации, а содержимое для текущей клиники лежит в `src/data/`. Маршруты страниц и их якоря используются в навигации и не требуют изменений при замене контента.

## Где редактировать

| Файл | Что менять |
| --- | --- |
| `src/data/clinic.js` | Название, слоган, логотип, favicon, видео футера, адрес, телефон, почта, соцсети, часы работы, запись, подпись и общий блок контактов |
| `src/data/navigation.js` | Названия пунктов шапки и меню, картинки и тексты предпросмотра |
| `src/data/home.js` | Два экрана hero, вступление, карточки «Почему выбирают нас», ссылки на услуги, философия, полноэкранное фото и галерея «До и после» |
| `src/data/about.js` | Вступление, фото и видео, команда, профили специалистов, шаги консультации |
| `src/data/services.js` | Hero услуг, каталог, сцена о подготовке и блок «Ваш путь к себе» |
| `src/data/seo.js` | Заголовок, описание и изображение для предпросмотра ссылок по каждой странице |
| `src/theme.css` | Общая палитра, шрифты, цвет и пропорции логотипа |
| `public/` | Медиафайлы, локальные шрифты, логотип и иконка вкладки |

### Бренд и контакты

1. Задайте `CLINIC.name` и `CLINIC.tagline`. Название подставляется в подписи, тексты и метатеги.
2. Положите логотип в `public/` и замените путь в `CLINIC.logo`, сохранив префикс `${base}`. Шапка и футер используют его как маску. Подходит SVG с прозрачным фоном. Если пропорции отличаются, укажите ширину и высоту через дробь в `--clinic-logo-aspect`.
3. Укажите `CLINIC.favicon` как путь относительно `public/`, например `brand/favicon.svg`. Заполните только подтверждённые контакты. Пустые адрес, телефон и email не выводятся. Для `socials` и `externalLinks` используйте объекты с полями `label` и `href`.
4. Настройте `openingHours`: у каждой группы укажите последовательные дни с одинаковыми часами. Таблица выводит отдельную строку для каждого дня, а меню показывает диапазон дней. Для непоследовательных дней создайте отдельные записи.
5. Заполните `bookingUrl` и проверьте `bookingLabel`, если у клиники есть рабочий канал записи. Пустой URL оставляет текст из `bookingStatus`. Год в подписи задаёт `copyrightYear`, отметку о демонстрации — `demoNote`.

### Изображения и видео

Положите файлы в текущий каталог `public/hero/`, `public/editorial/` или `public/before-after/` и укажите имя в данных. Префикс каталога уже учитывает путь Vite под GitHub Pages. Внутри строк с готовым префиксом добавляйте имя файла без начального `/`.

- В `HOME.hero` замените видео, постер и портреты для двух ширин. Укажите исходные размеры изображений и при необходимости измените `position` и `mobilePosition`.
- Для преимуществ меняйте `video` и `poster` каждой карточки в `HOME.whyChooseUs.reasons`. Сетка на десктопе рассчитана на четыре карточки.
- Hero на странице услуг по умолчанию использует то же видео, что и блок «Наша философия». Если нужен отдельный ролик, задайте свой путь в `SERVICES.hero.video`.
- В галерею добавьте объект в `HOME.approach.cases` с уникальным `id`, явными путями `before` и `after`, названием `procedure` и значением `landscape`. `position` позволяет уточнить кадрирование. Пустое `procedure` скрывает подпись под ползунком.

```js
{
  id: 5,
  procedure: "Коррекция губ",
  before: `${comparisonAssets}case-5-before.jpg`,
  after: `${comparisonAssets}case-5-after.jpg`,
  landscape: false,
}
```

### Услуги, команда и цвета

- Добавляйте направления в `SERVICES.catalog.groups`. Поле `id` должно быть уникальным и стабильным, поскольку оно создаёт якорь для прямой ссылки. Укажите `number`, `title`, `description`, `topics` и при наличии `image`. `imageAlt` переопределяет общий текст изображения каталога.
- Заполните массив `ABOUT.specialists.items`. Для каждого специалиста укажите имя, описание, изображение и при необходимости индивидуальные `role` и `position`. Пустое описание показывает текст из `ABOUT.specialists.placeholder`.
- В `theme.css` меняйте `--color-navy` для основного текста и акцентов, `--color-warm-white` для светлых фонов, `--color-white` для белых элементов, `--color-pale-grey` для нейтральных подписей и `--color-logo` для логотипа. Линии и подложки вычисляются из общей палитры. Семейства шрифтов задаются здесь же. Для нового локального файла шрифта подключите его в `src/fonts.css` и добавьте его лицензию в `public/fonts/`.

### SEO и проверка перед публикацией

1. Проверьте `SEO.home`, `SEO.services` и `SEO.about`. Поле `image` можно оставить пустым. Для Open Graph используйте полный HTTPS-адрес изображения, доступного после публикации.
2. Выполните `npm run build`. Проверьте `dist/index.html`, `dist/services/index.html` и `dist/about/index.html`: title, description, Open Graph и favicon уже должны быть в HTML. Если меняется имя репозитория на GitHub Pages, обновите `base` в `vite.config.js`.
3. Запустите `npm run preview`. Откройте три страницы по адресу с настроенным префиксом, проверьте навигацию, якоря, видео, ползунки, меню и мобильную версию. Проверьте ссылки на контакты и запись отдельно.
4. Перед публикацией замените на материалы новой клиники все демонстрационные фото, видео, кейсы и медицинские сведения из набора EK Clinic. Публикуйте только подтверждённые сведения и материалы, на использование которых есть разрешение. Демонстрационные фотографии и медицинские сведения одной клиники нельзя выдавать за данные другой.
